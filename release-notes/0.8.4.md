修复成员会话在旧审批等待结束后无法自动接续后续工作的情况。

- Git 按全局选项、子命令和子命令参数判断风险，修复把 `git grep -c` 的计数选项当作 `git -c` 配置覆盖的误判；常规拉取与查询复用已有长期授权，真正的配置覆盖、强制操作和外发仍单独确认。

- 修复 Windows `cd /d`、反斜杠和复合命令的目录授权识别。只读查询不再反复确认；目录常规授权可跨普通命令变化、应用重启以及工作恢复复用，删除、重置和越界操作继续单独确认。
- 修复 Windows 配置目录在日志或数据库文件持续变化时被误报权限不符；继续严格验证 ACL、所有者与目录身份，不放宽配置访问权限。
- 团队方案中新建的每位成员自动建立与用户的私聊，出现在会话列表；创建中断后核对已有结果恢复，不重复建群或创建成员。

- 当上一轮审批已结束、原执行已停止、会话独占锁可取得且审批范围核验通过时，后续独立请求可以恢复，不再因为消息来源不同而永久卡在“成员会话暂时无法接续”。
- 新工作保留自己的请求来源、成员范围和执行授权。只收尾已经结束的旧等待，不执行旧批次中的取消动作，也不重放已完成工具。
- 仍在等待、实际锁占用、审批执行结果不明、成员范围变化及人工暂停等情况继续保持保护；恢复操作持久化去重。
