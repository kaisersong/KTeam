## 关键处置核验（对照评审聚焦点）
1. **认领/移交闭环**（§6/§7/§14）：`claim(goalId,stepId,expectedRevision)` CAS、唯一 activeOwner、fencingVersion 统一约束系统派工、自荐与交接；租约过期先核验旧执行已停。交接 5 分钟超时、一次有界改派、回原 owner 并升级用户（A33/A35）。首轮单协调 pass、最多 3 成员、协调与执行均计费。满足“取名+说目标即可推进”，不退化为全员顺序应答。
2. **绑定与不静默换模型**（§11.2/§11.5/§16）：binding 含 expectedModelId/resolvedModelId/modelPolicy/bindingRevision，外部 CLI 无法证明时标 `agent_managed/unknown` 且不冒充锁定；额度/连续故障默认停止，仅用户选择或匹配事先明确的有界 fallback 才新建关联 run（A28/A39）。canonical registry 表、xiaok-cli 别名仅在探测证明同一 CLI 后迁移、P0a 含 catalog→canonical→项目/Room 正负例，覆盖当前 ID 兼容缺口；xiaok 协作空间与新 App 共用同服务同白名单（§11.4/A06）。
3. **小K助理**（§9/§9.1–9.3）：固定 thread 保留并单投影；publish/listSince/markRead/resolveReplyContext 调用方职责分离，Bot 不可写 readCursor；稀疏已读区间+连续水位、前台 1 秒可见或显式全读才推进（A29/A36）；回复解析优先级明确、歧义追问不猜测执行；semanticDeliveryKey 抑制晨报/事件重复且新实质变化生成新版本；follow-up 上限、Hide/snooze 不被默认重建、Bot 不可动用户 routine（A30）。
4. **权限/撤销/外发/停止**（§15）：动作四分类+有界常设授权，兼顾主动性与外发默认确认；紧急停止先 fence 阻新 admission 再 cancel，逐项汇报 stopped/stopping/unknown（A31）；撤销后投影/模型输入/导出失效，且诚实声明不承诺收回已看/已导出内容；A32 将“绕过范围负例实际被阻止，做不到即不授自动执行”设为硬门槛，`--plan`/提示词不算沙箱。
5. **首发现实性与测试可执行**（§17/§18/§18.1）：阶段映射完整，A13–A15/A21/A23–A25 安全底线不降级；40 条冻结语料含 4 类各 10 条，noop 10/10、必需成员召回≥90%、误唤醒≤2、零越权、≤1 次路由调用、首轮≤3 成员，未达只能“显式@内部预览”不得宣称首发完成（A37）；10 分钟无进展阈值与合法长 run deadline/心跳区分正确（A38）；标签由作者与独立评审核对、变更复跑、小样本不外推真实准确率，均为诚实表述。待探针收敛项（外部 Agent 候选、安装方式、实测默认值）均有明确验证路径与失败门槛，不构成缺验收。
